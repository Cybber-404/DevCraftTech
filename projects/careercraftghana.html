Overview

Prove the flow before you build the backend

CareerCraft Ghana helps job seekers build professional CVs and career documents. Rather than building the full backend first, the project started as a complete, clickable front-end prototype — 18 pages deep — so the experience could be validated before any real data was on the line.

Challenge

Making the jump from prototype to production safely

The prototype used fake data and simulated interactions by design. Migrating it to a real backend meant replacing every simulated flow — auth, payments, admin access — with the real thing, without losing the polish of the original design.

A closer look at the prototype also surfaced real risks before launch: password handling that only looked like hashing, an admin panel with no access gate, and a pricing settings form that silently failed to save.

Research & Planning

Designing the system before the schema

A dedicated teal & amber design system was built first, with shared CSS and JS modules so every one of the 18 pages stayed visually and behaviorally consistent — long before a single Supabase table existed.

Design Process

Consistency across 18 pages

Shared CSS and JS modules kept the teal (#0F766E, #14B8A6) and amber (#F59E0B) design language consistent from onboarding through document editing to the pricing page, so the eventual backend swap would be invisible to users.

Development

A real backend, built to hold up

Authentication was rewritten around Supabase's auth.* methods, and a proper async Postgres wrapper replaced the simulated data layer. Payments moved to Paystack's Inline.js, with a Supabase Edge Function handling server-side transaction verification.

The schema shipped with row-level security policies and security-definer admin RPCs, closing the gaps found during the audit — the encoded-not-hashed password, the ungated admin panel, and the broken pricing form were all fixed before launch.

Lessons Learned

Prototypes should be audited, not just admired

A polished clickable prototype can hide real security gaps once fake data becomes real data. Treating the prototype-to-production migration as a full security review — not just a data-layer swap — caught issues that would have been far costlier to fix after launch.
