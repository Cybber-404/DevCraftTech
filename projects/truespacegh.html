Overview

A listing platform that had to earn trust first

Ghana's rental market runs largely on word of mouth and informal listings. TrueSpaceGh needed to feel more credible than a classifieds board — with clear listing tiers, verified-feeling admin tooling, and a visual identity that reads as established rather than experimental.

Challenge

Outgrowing a single-file prototype

The original build was a fast, functional single-file vanilla JS/CSS app — great for validating the idea, but difficult to extend safely as the feature set grew (plan tiers, an admin dashboard, social sharing metadata).

Any refactor had to preserve exact visual and functional behavior. There was no room for regressions in a live, in-use product.

Research & Planning

Mapping the app before touching a single file

Before any refactor work began, the existing monolith was mapped feature-by-feature — listing plans, the admin dashboard, the mosaic property grid, OG meta tag injection for social sharing, and the SPA router — so nothing would be lost in translation to a modular structure.

Design Process

A warm, credible visual identity

The rebrand moved away from a generic listings look toward a warm cream/tan palette anchored on #C9A876, paired with a mosaic property grid that gives listings more visual weight than a plain card grid.

The homepage was split so brand storytelling and property browsing no longer competed for the same space — storytelling lives on the homepage, and a dedicated /properties route handles filtering via query-string parameters.

Development

From monolith to modular, with auth hardened along the way

The backend moved from in-memory storage to SQLite via Node's built-in node:sqlite module. A listing plan system (STANDARD / FEATURED / PREMIUM) was added with tsghId, paymentStatus, and listingStatus fields, alongside an admin dashboard for listing management.

Authentication was hardened by moving credentials to environment variables, adding a server-side login endpoint with HMAC-SHA256 signed tokens, a 12-hour session TTL, and IP-based brute-force lockout. Display-context output was passed through a client-side escaping helper to close XSS gaps, while edit-form inputs were deliberately left untouched to avoid double-encoding.

A latent SPA router bug was also caught along the way — the initial render() call was silently stripping query strings — and fixed before it reached production.

Lessons Learned

Maintainability over architectural purity

The guiding principle throughout the refactor was maintainability over architectural purity — splitting the codebase to make it easier to reason about, not to satisfy an abstract ideal. Rigorous verification (visual diffing plus token-level string comparison) made it possible to move fast on a live product without breaking it.
