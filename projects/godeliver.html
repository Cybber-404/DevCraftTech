Overview

One platform, three very different roles

GodDeliver needed to serve customers placing orders, riders fulfilling them, and admins overseeing the whole operation — each with distinct dashboards, permissions, and real-time needs, all built on a shared Firebase backend.

Challenge

Trustworthy tracking and fair pricing, live

Customers needed to see exactly where their order was, in real time, without refreshing. Fares had to reflect actual distance rather than flat guesses, and riders needed a way to claim unassigned orders without stepping on one another.

Early Firestore security rules were too restrictive — one rule accidentally blocked riders from claiming unassigned orders — and had to be iteratively corrected without opening the system up to abuse.

Research & Planning

Designing around the order lifecycle

The core of the platform is a five-stage order lifecycle — pending, assigned, pickup, in transit, delivered — and every dashboard, notification, and permission rule was planned around keeping that lifecycle consistent across all three roles.

Design Process

A dashboard for every role

Google Sign-In with a role-picker modal gets people into the right dashboard from the first tap. Riders get an Earnings, Active Orders, and Wallet view built around Mobile Money withdrawals — the payout method that actually matters in this market.

A real-time notification system, backed by Firestore unread-count badges and batched mark-all-as-read writes, keeps every role aware of order changes without hammering the database.

Development

Real-time by default

Order tracking runs on Firestore's onSnapshot listeners, Google Maps Places Autocomplete handles address entry, and phone OTP verification was added at signup across every role. The platform was later rebranded from NationGo to GoDeliver across 19 files without breaking a single existing flow.

Lessons Learned

Security rules deserve the same testing as features

A permissions rule that looks correct on paper can still quietly block a legitimate action — in this case, riders claiming unassigned orders. Testing security rules against real role-based workflows, not just the happy path, caught it before it became a support problem.
